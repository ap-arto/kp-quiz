# KP Quiz — специфікація MVP

Мініпроєкт для підготовки до співбесіди на Карту поляка. Статичний фронтенд на React, публікація на GitHub Pages. Основний сценарій — використання з телефона (приблизно 90% відвідувань).

## Узгоджені вимоги

### Головний екран

- Вибір категорії.
- Для кожної категорії: кількість унікальних опрацьованих питань відносно загальної кількості та відсоток правильних відповідей за всіма спробами.
- Два режими: швидкий квіз (10 питань або всі, якщо їх менше) і повний квіз по всій категорії.
- Перемикач мови інтерфейсу: українська / польська. Вибір зберігається локально.

### Підбір питань

- Питання без жодної відповіді мають найвищий пріоритет.
- Далі — питання за зростанням частки правильних відповідей (`successes / attempts`).
- За однакових показників питання обираються випадково.
- У швидкому квізі підбір обмежується 10 унікальними питаннями вибраної категорії.
- Повний квіз охоплює кожне питання категорії один раз.
- Чотири варіанти відповідей перемішуються при кожному проходженні; правильність прив'язана до ідентифікатора відповіді, а не її позиції.

### Екран питання

- Текст питання та чотири варіанти, серед яких рівно один правильний.
- Натискання одразу фіксує відповідь і оновлює статистику; змінити відповідь або зарахувати її повторно неможливо.
- Після відповіді показуються правильний варіант і замітка-факт.
- Перехід далі — лише кнопкою «Наступне питання», без автоматичного переходу.

### Підсумки

- Кількість правильних відповідей і відсоток за поточне проходження.
- Список питань, на які відповіли неправильно, з правильними відповідями та замітками-фактами.
- Кнопка «До категорій».
- Функції «Повторити помилки» немає.

### Збереження

- `localStorage`: кількість відповідей (`attempts`) і кількість правильних відповідей (`successes`) для кожного стабільного `id` питання, а також вибрана мова інтерфейсу.
- Статистика записується після кожної відповіді, навіть якщо квіз не завершено.
- Поточне проходження не зберігається. Після закриття або перезавантаження сторінки користувач починає заново.
- Опрацьоване питання — питання з `attempts > 0`.
- Успішність категорії: `sum(successes) / sum(attempts) * 100`. За відсутності спроб показуємо «—».
- Статистика локальна для браузера, без акаунтів і синхронізації.

### Контент та i18n

- Питання й категорії беруться з JSON-файлу.
- Категорія має стабільний `id` та назви українською і польською.
- Питання має стабільний `id`, категорію, текст, чотири варіанти, правильну відповідь і замітку-факт.
- Мова текстів питань, відповідей і фактів визначається самим JSON; застосунок їх не перекладає.
- Усі тексти інтерфейсу локалізовані через i18n українською та польською.
- Реальний набір питань складемо окремо, використовуючи `/Users/thomas/work/kp-data` як джерело.

### Візуальний стиль

- Mobile-first.
- Світлий теплий фон, близький до пергаменту, без чисто білого як основного фону.
- Темний читабельний текст, приглушений червоний акцент.
- Мінімалістичний інтерфейс і великі кнопки відповідей.
- Помилку позначаємо також текстом та іконкою, щоб вона не залежала лише від кольору й відрізнялася від акценту.

## Запропонована структура JSON

Назви полів — технічна пропозиція для реалізації. Приклад нижче містить лише заповнювачі, а не навчальний контент.

```json
{
  "categories": [
    {
      "id": "history",
      "name": { "uk": "Історія", "pl": "Historia" }
    }
  ],
  "questions": [
    {
      "id": "history-001",
      "categoryId": "history",
      "question": "Текст питання",
      "answers": [
        { "id": "a", "text": "Варіант A" },
        { "id": "b", "text": "Варіант B" },
        { "id": "c", "text": "Варіант C" },
        { "id": "d", "text": "Варіант D" }
      ],
      "correctAnswerId": "b",
      "fact": "Пояснення правильної відповіді"
    }
  ]
}
```

Ідентифікатори питань мають бути унікальними в усьому наборі та залишатися незмінними під час виправлення текстів. Для кожного питання потрібні рівно чотири різні ідентифікатори відповідей, наявний `correctAnswerId` та наявна категорія.

## Технічні рішення для реалізації

- React — обраний користувачем стек.
- TypeScript — запропонований для типізації контенту й статистики.
- Три екрани можуть працювати в одному статичному застосунку без окремих URL; окрему маршрутизацію користувач не вимагав.
- Завантаження ресурсів має працювати в підкаталозі репозиторію на GitHub Pages.
- Конкретний репозиторій та адреса публікації поки не визначені.
- Незадані дрібні рішення (наприклад, початкова мова або порядок повного квізу) залишаються на етап реалізації.

## Критерії готовності

- Обидва режими працюють у межах вибраної категорії без повторення питань за одне проходження.
- Нові питання мають пріоритет перед питаннями зі спробами, слабші — перед сильнішими.
- Перемішування відповідей не змінює правильний варіант.
- Одну відповідь зараховуємо рівно один раз; статистика зберігається після перезавантаження, поточна сесія — ні.
- Підсумок відповідає поточному проходженню; розбір містить лише питання з помилками.
- Перемикання мови перекладає інтерфейс і назви категорій, не змінюючи контент питань.
- Інтерфейс зручний на вузькому мобільному екрані та доступний із клавіатури.
- Статична збірка працює на GitHub Pages у підкаталозі репозиторію.
